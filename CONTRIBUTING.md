# Contributing to Unfold

## Development setup

Requires Node.js 20 or later.

```sh
git clone https://github.com/faizm10/unfold.git
cd unfold
npm install
npm run build
npm link            # puts your local `unfold` on PATH
```

`npm run build` compiles `src/` to `dist/`. Rebuild after changes, or run `npx tsc -p tsconfig.json --watch` (you still need `node scripts/copy-ui.mjs` once for the browser view's static files).

## Tests

```sh
npm test            # builds first, then runs every test
npm run typecheck
```

- `test/vercel-parser.test.ts`: the Vercel parser, line by line.
- `test/pipeline.test.ts`, `test/fix-prompt.test.ts`: demo transcripts through the full pipeline.
- `test/tui.test.ts`: the terminal summary, live panel and explorer screens.
- `test/e2e.test.ts`: runs the built `unfold` binary in a real pseudo-terminal against `test/fixtures/fake-vercel.mjs` and checks what a terminal displays. It needs node-pty and is skipped on Windows.

To try the live terminal path without deploying anything, point Unfold at the fake CLI:

```sh
UNFOLD_VERCEL_BIN=$PWD/test/fixtures/fake-vercel.mjs FAKE_VERCEL_PROMPT=1 unfold vercel
FAKE_VERCEL_DEMO=build-failure UNFOLD_VERCEL_BIN=$PWD/test/fixtures/fake-vercel.mjs unfold vercel
```

Demo transcripts in `demos/` are generated by `node scripts/make-demos.mjs`.

## How it's built

```
src/core/          shared and provider-agnostic
  model.ts         event model: Signal, RunEvent, FlowState
  terminal.ts      PTY bytes → lines (ANSI, OSC links, spinner redraws)
  redact.ts        secret redaction
  flow.ts          reducer: signals → stage states (confirmed / unverified rules)
  session.ts       decoder → redactor → provider parser → reducer
  launch.ts        node-pty passthrough (falls back to pipes)
  server.ts        optional browser view (--web) over Server-Sent Events
src/tui/           terminal views
  panel.ts         live panel pinned below the command's output (scroll region)
  render.ts        flow line and end-of-run summary
  explore.ts       full-screen explorer (`unfold show`)
src/providers/
  provider.ts      the interface a provider implements
  vercel/          stage text, launch args, and the output parser
src/ui/            the browser page (plain TypeScript, no framework)
demos/             recorded transcripts (regenerate: node scripts/make-demos.mjs)
```

To add a provider such as `gcloud`, add a `src/providers/gcloud/` folder with stage definitions, a `launch()` function and a parser that turns lines into `Signal`s, then register it in `src/providers/index.ts`. Nothing in `core/` needs to change.

## Supporting a new Vercel CLI output format

If a Vercel CLI release prints something Unfold doesn't recognize:

1. Save the output, with secrets removed, from a real run. `~/.unfold/runs/<run>.jsonl` already contains the redacted lines.
2. Add the new lines as test cases in `test/vercel-parser.test.ts`.
3. Update `src/providers/vercel/parser.ts`. Keep the rule that a stage is only confirmed by output that proves it.

## Pull requests

- Run `npm test` and `npm run typecheck` before opening a PR. CI runs them on macOS, Linux and Windows with Node 20 and 22, and also installs the packed tarball to check that it works.
- Keep provider-specific code in `src/providers/<name>/`.
- Never log, store or send environment variables, and run anything new that displays or saves output through the redactor.

## Releasing

1. Update the version in `package.json` and add an entry to `CHANGELOG.md`.
2. `npm publish` (runs the full test suite first via `prepublishOnly`).
